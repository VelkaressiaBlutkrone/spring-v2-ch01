## 1. 프로젝트 개요

## 1. 보안 설정 (Security)

본 프로젝트는 Spring Boot, Gradle, Spring Data JPA를 기반으로 구축된 JWT 인증 방식의 RESTful API 서버입니다. 주요 기능은 사용자 관리, 게시판, 댓글 기능이며, 역할 기반(USER, ADMIN)으로 API 접근 제어를 구현합니다.

**CORS 설정**: 시큐리티 설정(Security Config) 단계에서 CORS(Cross-Origin Resource Sharing) 필터를 적용해야 합니다.

## 2. 기능 구현 (Feature Implementation)

### 2.1. 사용자 및 인증 (구현 완료)

**회원 정보 조회**:

- **목표**: 회원가입된 유저의 정보를 조회하는 기능 구현.
- **API 엔드포인트**: `api/user/{id}`
- **구현 위치**: `UserController`
- **회원가입 (`POST /join`)**
  - `username`, `password`, `email`을 받아 사용자를 등록합니다.
  - `username`과 `email`은 중복될 수 없습니다.
  - 비밀번호는 BCrypt 알고리즘으로 암호화하여 저장합니다.
- **로그인 (`POST /login`)**
  - `username`, `password`를 받아 인증을 수행합니다.
  - 인증 성공 시, 해당 사용자의 정보를 담은 JWT(JSON Web Token)를 발급하여 응답 헤더에 포함시킵니다.
- **유저네임 중복 체크 (`GET /check-username`)**
  - 쿼리 파라미터로 받은 `username`의 사용 가능 여부를 확인합니다.
- **API 접근 권한**
  - 인증 관련 API(`join`, `login`, `check-username`)를 제외한 모든 API 호출은 유효한 JWT 토큰을 필요로 합니다.

## 3. 코딩 컨벤션 (Coding Convention)

- **게시글 작성 (`POST /api/boards`)**
  - `USER` 또는 `ADMIN` 권한이 필요합니다.
- **게시글 목록 조회 (`GET /api/boards`)**
  - `USER` 또는 `ADMIN` 권한이 필요합니다.
- **게시글 상세 조회 (`GET /api/boards/{id}`)**
  - `USER` 또는 `ADMIN` 권한이 필요합니다.
- **게시글 수정 (`PUT /api/boards/{id}`)**
  - `USER` 또는 `ADMIN` 권한이 필요하며, 자신의 게시글만 수정 가능해야 합니다.
- **게시글 삭제 (`DELETE /api/boards/{id}`)**
  - `USER` 또는 `ADMIN` 권한이 필요하며, 자신의 게시글만 삭제 가능해야 합니다.

  **메서드 패턴**: `UserController`의 메서드 작성 시, 기존 `AuthController`의 구현 패턴을 참고하여 동일한 스타일을 유지해야 합니다.

### 2.3. 댓글 (기능 명세)

> **참고:** 현재 컨트롤러 및 서비스 로직이 구현되어 있지 않은 스켈레톤 상태입니다.

- **댓글 작성 (`POST /api/replies`)**
  - `USER` 또는 `ADMIN` 권한이 필요합니다.
- **댓글 삭제 (`DELETE /api/replies/{id}`)**
  - `USER` 또는 `ADMIN` 권한이 필요하며, 자신의 댓글만 삭제 가능해야 합니다.

### 2.4. 관리자 (기능 명세)

> **참고:** 현재 컨트롤러 및 서비스 로직이 구현되어 있지 않은 스켈레톤 상태입니다.

- **/api/admin/** 경로의 모든 API는 `ADMIN` 권한을 가진 사용자만 접근 가능합니다.
- 구체적인 관리자 기능은 아직 정의되지 않았습니다.

## 3. 아키텍처 및 기술 스택

- **Framework**: Spring Boot
- **Build Tool**: Gradle
- **Data Access**: Spring Data JPA
- **Security**: Spring Security, JWT (JSON Web Token)
- **Password Encoding**: BCrypt
- **API Style**: RESTful

## 4. 데이터 모델 (JPA Entities)

- **`User`**
  - `id`: PK
  - `username`: 사용자 아이디 (Unique)
  - `password`: 비밀번호 (BCrypt 암호화)
  - `email`: 이메일 (Unique)
  - `role`: 역할 (ex: "USER", "ADMIN")
- **`Board`**
  - `id`: PK
  - `title`: 제목
  - `content`: 내용
  - `user`: 작성자 (N:1 관계)
  - `replies`: 댓글 목록 (1:N 관계)
- **`Reply`**
  - `id`: PK
  - `comment`: 댓글 내용
  - `user`: 작성자 (N:1 관계)
  - `board`: 게시글 (N:1 관계)

## 5. Security 설정 (`SecurityConfig.java`)

- **Stateless Session**: 세션을 사용하지 않는 상태 비저장(Stateless) 서버로 동작합니다.
- **JWT Filter**: `JwtAuthorizationFilter`를 통해 모든 요청의 헤더에서 JWT를 검증합니다.
- **CORS**: `application.properties`에 정의된 `app.cors.allowed-origins`의 출처를 허용합니다.
- **CSRF**: 비활성화 처리되어 있습니다.
- **권한 제어 (Authorization)**
  - `/api/admin/**`: `ADMIN` 역할 필요
  - `/api/users/**`, `/api/boards/**`, `/api/replies/**`: `USER` 또는 `ADMIN` 역할 필요
  - 그 외 모든 요청: 누구나 접근 가능
- **인증/인가 예외 처리**: 인증 실패 시 401 Unauthorized, 인가 실패 시 403 Forbidden 응답을 반환합니다.
